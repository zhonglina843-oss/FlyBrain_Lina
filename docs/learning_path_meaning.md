# 这五步分别在解决什么问题

这不是“依次安装五个软件”。它是一条从**真实数据**到**建模假设**再到**外部应用**的溯源路线。

```mermaid
flowchart LR
    A[1 官方连接组事实] --> B[2 全脑动力学假设]
    B --> C[3 视觉模型的训练边界]
    C --> D[4 游戏/浏览器的工程映射]
    D --> E[5 把人工设定逐项列出]
```

| 步骤 | 具体问题 | 你会得到什么 | 它排除的误解 |
|---|---|---|---|
| 1. Codex 回路查询 | 官方数据中，哪些细胞存在、在哪一侧、是否真的有一条边？ | 可复查 ID、类型、连接 weight 和版本记录 | 不把游戏 README 当连接组事实 |
| 2. 官方全脑 LIF | 给真实图补上 LIF 方程后，刺激如何传播？ | 输入 spike、全脑响应、沉默/激活实验 | 不把“有连接”误认为“自动有活动” |
| 3. flyvis | 哪些参数仍需训练，训练如何受 connectome 约束？ | 预训练模型、光流输入、预测神经响应 | 不把固定 wiring 误认为零训练 |
| 4. 第三方游戏 | 如何把模型输出接到移动、鼠标或角色动作？ | 输入编码、readout、环境反馈的具体代码位置 | 不把游戏行为全部归因于大脑 |
| 5. 横向比较 | 每个项目额外加入了哪些人为假设？ | 一张假设对照表和可复现微调计划 | 不夸大模拟器的生物学结论 |

## 第一步为什么必须先做

连接组是一个特定版本、特定性别、特定个体的图。`LC4`、`LPLC2`、`DNp01` 这些名字在不同数据集、版本和性别中可能有不同覆盖或注释状态。第一步先记录官方 ID 和直接连接，后面每一步才有同一条“事实基线”。

否则会发生三个问题：

1. 用 MaleCNS 的通路名称去解释 FlyWire 雌蝇数据；
2. 把第三方人为筛选后的图当作原始连接组；
3. 改了模拟参数后，无法判断变化来自真实 wiring 还是代码作者的输入/输出规则。

## 每一步的停止点

### 1. 数据

停止于：已保存类型、代表性 root ID、直接边与数据版本。不要在这一步解释行为。

### 2. 动力学

停止于：能复现官方模型的激活与沉默实验。不要在这一步接入游戏。

### 3. 训练

停止于：能区分“固定拓扑”和“训练的共享参数”。不要把预训练 checkpoint 当作原生果蝇状态。

### 4. 应用

停止于：能画出从像素/刺激到动作的全部映射。不要把 UI 或物理引擎的规则藏在“大脑涌现”说法里。

### 5. 比较

停止于：每一个额外假设都有代码位置、默认值和改动后的结果。
